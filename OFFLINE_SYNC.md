# Offline Sync & Backup Strategy — One Percent

This document details the offline resilience, conflict resolution, retry queue, and JSON backup architecture for **One Percent**.

---

## 1. Offline Sync Queue Architecture

The offline mutation queue is managed by `lib/services/sync-queue.service.ts`.

### Key Mechanics:
- **Queue Items**: `{ id, entityType, entityId, action, payload, clientTimestamp, attemptCount, status }`.
- **Deduplication**: Successive updates for the same entity id before network flush are merged idempotently into a single operation.
- **Exponential Backoff**:
  $$\text{DelayMs} = \min\left(30000, 1000 \times 2^{\text{attemptCount}}\right)$$
  Max retries: 5 attempts per operation.
- **Conflict Resolution**: Last-Write-Wins (LWW) based on `clientTimestamp` vs server timestamp.
- **Auto-Recovery**: Listens to `window.addEventListener("online")` to automatically flush pending operations upon network reconnection.

## 2. Backup & Disaster Recovery JSON Schema

Backup export payloads generated by `lib/services/backup.service.ts` follow this specification:

```json
{
  "app": "One Percent",
  "version": "1.0.0",
  "schemaVersion": 1,
  "exportedAt": "2026-08-07T18:30:00.000Z",
  "checksum": "a3f89e",
  "data": {
    "workouts": [],
    "programs": [],
    "templates": [],
    "exercises": [],
    "goals": [],
    "weightLogs": [],
    "bodyMeasurements": [],
    "habits": [],
    "recovery": []
  }
}
```

### Restore Modes:
1. **Merge Restore (Default)**: Combines imported payload with existing local storage entities, resolving duplicate IDs safely.
2. **Full Replacement**: Replaces local state stores with imported JSON data snapshot.
